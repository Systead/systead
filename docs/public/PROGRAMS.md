# Programs

A Systead **Program** is a deep specialist application that operates inside a House while sharing the same memory, authority, privacy, audit, recovery, and export foundations.

Programs are not separate data kingdoms. They cooperate through Systead Core.

## Program 01: Publishing

The first Program serves authors and publishing operations.

Its current internal working name is **AuthorMachine**.

That name is not yet locked as the public release name. The eventual name, package, feature boundaries, price, licence, and release identity may change.

Current private-build direction includes or explores:

- project and book cockpits;
- manuscript and revision state;
- canon and continuity;
- characters, locations, timelines, and rules;
- decisions, contradictions, plot holes, and proofing;
- editions and formats;
- metadata, pricing, rights, and catalogue;
- production and release work;
- ARC, reviewer, contact, and outreach operations;
- controlled exports and publishing destinations;
- source-aware assistance.

This is a direction map, not a final release checklist.

## Why publishing first?

Publishing combines long-lived projects, many versions, creative decisions, external releases, rights, contacts, and correction history. It is a strong test of whether Systead can preserve continuity without taking control away from the operator.

## The architectural rule

Shared capabilities move into Core. Publishing-specific depth stays in Program 01.

Examples:

- generic decisions → Core;
- canon and continuity → Program 01;
- generic contacts → shared House records;
- ARC workflows → Program 01;
- command review → Core;
- publishing-platform adapters → Program 01 or Connectors.

The public line is:

> **One House. Many Programs. Publishing is the first.**
