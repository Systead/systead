# Security Policy

Systead is pre-alpha and not yet suitable for production secrets or high-risk data.

## Report privately

Do not publish vulnerabilities, exposed personal data, credentials, or private House exports in a public issue. Until a dedicated security address is configured, use the private contact route listed on Systead.com or contact the repository owner directly.

## Current boundaries

- No telemetry by default.
- No automatic publishing, payment, banking, or message sending.
- Secrets must not be stored in committed configuration.
- Private House data must never be used as demo content.
- Destructive commands require explicit risk, backup, confirmation, audit, and rollback behaviour.
