
# Platform versus Programs

## Canonical distinction

> **Programs solve particular domains. Systead preserves the whole.**

Systead is the platform, product ecosystem, and broader company direction.

A House is the operator's configured environment.

A Program is optional specialist depth inside the House.

## Durability rules

- Programs are replaceable.
- The House is durable.
- No Program owns the person.
- Shared continuity capabilities belong in Core.
- Specialist domain models belong in the relevant Program.
- Removing a Program must not destroy unrelated House memory.
- A Program cannot bypass Core authority, privacy, audit, recovery, or export contracts.
- Public presentation must not allow Program 01 to become the definition of Systead.

## Program 01 naming

AuthorMachine is the current internal working name for Program 01: Publishing and the private v10 line.

It is not a locked public release name. Feature presence in the private build is not a release promise.

## Future Programs

Architecture may be tested against possible future domains. Such examples remain design probes unless a Program is formally approved, named, scoped, and added to the roadmap.
